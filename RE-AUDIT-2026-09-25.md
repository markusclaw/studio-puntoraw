## New bugs introduced by the overnight work (verified, ranked)

**N1 — Admitted guest gets kicked to preflight on any WS blip, can double-connect.** HIGH
`room-client.js:29` sets `this.joined=false` *before* emitting `offline`, so the new branch at
`greenroom.html:284` `if(!client.joined)` is always true. Scenario: admitted guest on air, 1 s
blip → "Room service unreachable", preflight shown, Enter re-enabled; guest clicks Enter →
second `RawRoomClient` with the same identity while the first is auto-reconnecting → worker
`replaced` → first client's `fatal` → `stopPublisher()` → guest camera drops from the program.
Fix: `let everJoined=false;` set true in the `joined` handler; branch on `!everJoined`.

**N2 — "Take control" bypasses the lease during the holder's blip.** MEDIUM (undermines 1.4)
`index.js:139` `live = hostId && expiresAt>now && members.some(holder)` — the `members.some`
clause lets RJ/Rafa claim while Greg's socket is down for 3 s, even though `nextBadgeHolder`
would have kept Greg. Fix: `const live=this.badge.hostId && this.badge.expiresAt>Date.now();`
and make `host.js:403` `holderPresent` lease-based (`badge.expiresAt` vs `serverTime`).

**N3 — A denied/removed guest can never be re-admitted.** MEDIUM
`index.js:147` sets `denied=true`; `host.js:119` `knockingGuests()` filters `!m.denied`, and no
other UI lists denied guests. A mis-click on Deny/Remove locks the guest out until the 60 s
purge + a reload. Fix: render denied guests in the tray as "Denied — re-admit" (admit already
resets `denied=false`).

**N4 — Meshcast upload is uncapped.** MEDIUM, TEST
`hostcam.js:32` / `greenroom.html:246` use `videobitrate=2500`, which is a viewer-side request
parameter; with `meshcast=video` the relay leg is capped by `meshcastbitrate` (and
`meshcastscale`). Fix: add `meshcastbitrate:'2500'` (keep `videobitrate` for the P2P fallback).

**N5 — Guests still decode every host at full rate.** MEDIUM, TEST
`greenroom.html:246` has `meshcast` but no `novideo` — the exact 2.1 cost, now on the weakest
device (a guest's phone). Fix: `novideo:''` (or `scale=25` if guests must see hosts).

**N6 — "Camera connected" still asserted before anything is published.** LOW
`hostcam.js:46` flips to live on `joined-room`/`loaded`, both of which precede getUserMedia.
Denied camera permission shows "Camera connected". Fix: `['video-created','started']` only,
plus a 15 s timeout back to `off` with a toast.

**N7 — Stage height budget ignores the new session bar.** LOW
`styles.css:2594` still subtracts `56+58+310`; the Season/Episode bar added a grid row
(`styles.css:456`), so on short windows the desk is pushed down ~40 px again. Subtract it.

**N8 — Double connect on every greenroom hand-off.** LOW
Greenroom sets both `raw.host.seat` and `raw.host.enter`; host.js auto-rejoins, then the
`raw.host.enter` script (`index.html:896-918`) submits the gate and reconnects. Harmless
(worker replaces same-id), but it costs a join/reconcile/broadcast and a spurious offline
render. Fix: skip the `raw.host.enter` path when `raw.host.seat` is set.

**N9 — Slot-keyed tiles collapse duplicates.** LOW
`program.js:101`: two boxes for one slot (only reachable via manual add/drag, `app.js:2258`)
render as one tile. Fall back to `box.id` when a slot repeats — or finish 4.4 and remove the
manual path.
